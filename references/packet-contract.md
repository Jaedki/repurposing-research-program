# Content packet contract

This file is the maintainer-facing reference for worker tasks, scientific gates, and result fields.
The persisted packet emitted by the installed controller is the operative contract for a worker.
Controller state and stage ownership live in [architecture.md](architecture.md); source-service and
adapter behavior lives in [source-adapters.md](source-adapters.md).

`next` writes one packet. While that task remains ready, repeated `next` calls and `submit` read the exact persisted packet; an issued packet is never regenerated in place. Item packets include a stable `item_id`; global packets use `null`. Every packet contains the case, one task, hashes of accepted canonical barriers, only the task context, exact result fields, and evidence rules.

The worker returns one JSON object:

```json
{
  "stage": "pathology_node_research",
  "item_id": "NODE-...",
  "packet_id": "PACKET-...",
  "status": "complete",
  "records": {},
  "gaps": [],
  "notes": []
}
```

The packet also supplies an exact top-level `result_template`, a row template for every collection,
and a non-accepting `validation_command`. Workers validate and repair only the reported invalid
field and direct dependants before submitting; preflight never accepts or rewrites a result.

## Agent task collections

1. `pathology_source_adjudication`: `sentence_decisions`; one compact packet partitions every flagged free-text sentence exactly once as `retain_pathology`, `exclude_treatment`, `exclude_mixed`, or `exclude_ambiguous`. It performs no search or rewriting and is skipped deterministically when the batch is empty.
2. `pathology_landscape_scan`: `documents`, `landscape_proposals`, `asta_call_receipts`, `coverage_checks`; one global, shallow Asta scan runs one stable broad search and focused searches until every coverage gap is terminal. Zero proposals are valid after at least one completed search and a complete coverage register.
3. `pathology_coverage_expansion`: `documents`, `coverage_proposals`, `undermind_search_receipts`; one named Undermind search challenges the complete post-Asta index and must return one completion receipt reporting at least one ranked result. An empty search shell or other operational failure keeps the packet active.
4. `pathology_curation`: `concepts`; one packet partitions every supplied non-anchor Monarch, DisMech, and projected Asta or Undermind node exactly once and is the only packet that decides splits, merges, final concept identity, and research eligibility.
5. `pathology_node_research`: `documents`, `profiles`, `assertions`.
6. `pathology_open_questions`: `open_questions`; one graph-wide packet generates broadly, challenges candidate questions against the frozen graph, and returns one to ten material unanswered questions with an exact unresolved basis and discriminating evidence requirement, without researching them or assigning gap types.
7. `pathology_question_research`: `documents`, `question_answers`; one packet researches and partitions every supplied question exactly once as `corpus_sufficient`, `literature_delta_found`, or `still_unresolved`, retaining new papers only when they support a material answer delta, counterclaim, or alternative explanation.
8. `pathology_hypothesis_synthesis`: `documents`, `question_node_tags`, `hypothesis_connections`; one packet tags every question and retained connection with all mechanistically relevant frozen nodes while generating, comparing, and challenging claim-anchored connections; an empty connection set is valid.
9. `candidate_seed_research`: `documents`, `rescue_strategies`, `context_dispositions`, `candidates`, `exclusions`; before drug searching, the worker derives one or more cited directional rescue strategies owned by the focal primary node, without seeking a quota.
10. `candidate_identity`: `documents`, `identity_groups`; one global packet partitions every UniChem-flagged or unresolved seed exactly once. It is skipped deterministically when the queue is empty.
11. `candidate_evidence_review`: `documents`, `reviews`; one packet contains the identity-resolved candidates assigned to one pathology concept and requires exactly one evidence dossier per supplied candidate.
12. `candidate_audit`: `assessments`, `excluded_candidates`, `evidence_dispositions`; one global closed-corpus packet requires an exact partition of every reviewed candidate and cannot return new documents.

Python creates `pathology_source_screening`, `pathology_sources`, the frozen `evidence_graph`,
UniChem-enriched `candidate_seed_generation`, and aggregated `candidate_review` results.

Research `document_id` values use a canonical PMID, PMCID, DOI, namespaced Semantic Scholar paper ID (`S2:` followed by 40 hexadecimal characters), supported authoritative database accession, or HTTPS URL; the generated packet contract lists the exact accepted formats. Invented `DOC-AUTHOR-YEAR` aliases are rejected. Every returned document contains one or more `evidence_passages` objects with exactly non-empty string values for `text` and `locator`; a citation record without inspectable retained content is invalid.
For PMID, PMCID, and DOI documents, Python uses cached authoritative metadata to verify that the supplied title belongs to the identifier and projects the canonical publication ID, known identifier aliases, title, year, journal, and authors downstream. One worker result cannot return the same publication through two identifier aliases. Accepted worker results remain unchanged. Python keeps one document per submitted ID and unions list evidence without duplicates. Publication-title conflicts remain strict; supported HPA, UniProt, Reactome, QuickGO, and Bgee accessions accept record-label variants only when normalized entity tokens remain consistent.

Workers may search and read freely, but `records.documents` contains only underlying documents that directly support a submitted claim, counterclaim, identity decision, or limitation. Each returned document ID is cited through `source_ids`, `pathology_source_ids`, or `mechanism_source_ids` somewhere in that result, including nested observation citations. Upstream citations need not be returned again.

Python preserves accepted results unchanged and applies this rule as a soft propagation boundary: unused returned documents are normally not rejected, but do not enter aggregated stages or downstream packets. The two pathology-discovery stages and the two global research/synthesis stages are stricter and reject papers not cited by a proposal, claim, or connection. The graph, seeds, identity review, and candidate review each contribute only their own cited documents. Question-research and connection-synthesis documents support discovery leads but do not enter the audit corpus unless independently retrieved and cited downstream. `_all_documents()` assembles the deduplicated retained cross-stage union for the auditor and final outputs, including cited evidence for excluded candidates and negative findings but excluding papers attached only to rejected Asta or Undermind proposals or to global hypothesis stages without independent downstream citation.

## Pathology records

- Structured treatment sections and fields are excluded before sentence screening. The screening
  batch contains deduplicated sentence IDs, exact sentences, bounded signal classes, and source
  paths. The adjudicator returns decisions only; it cannot create nodes, return documents, or
  introduce replacement text. Python restores only exact sentences classified
  `retain_pathology`; mixed and ambiguous sentences fail closed and become explicit gaps.

- The landscape packet contains the compact initial pathology index and a complete coverage
  register. `landscape_proposals` contain exactly `label`, `provisional_type`, `claim`,
  `index_comparison`, and `source_ids`; each cites returned canonical evidence. Zero proposals are
  valid after at least one completed relevance search and terminal classification of every gap.
  `asta_call_receipts` record the bounded non-secret fields supplied by the packet. Every coverage
  check names the completed search operation IDs that tested it; resolved checks cite retained
  proposal sources, and searched-unresolved gaps include a focused search.

- The coverage-expansion packet contains the complete post-Asta index and upstream gaps.
  `coverage_proposals` use the same scientific shape and cite canonical full-text evidence.
  `undermind_search_receipts` must record a completed search with a positive ranked-result count
  and a complete ranked-result ID list plus a compact disposition for every paper actually read,
  including papers not retained.
  The operational call, retry, recovery, polling, inspection, batching, and transient-data rules for
  both services are defined once in [source-adapters.md](source-adapters.md).

- Monarch, DisMech, and projected Asta or Undermind nodes are disease-specific claims with a provisional type and retained sources. Each literature proposal contains one pathological state or process at one causal level; one paper may support several separate proposals. The curator assigns the authoritative run-local concept type from the supplied claim, payload, and edges; literature-service proposals have no privileged status.
- Non-node DisMech material is retained in `disease_context`. The curator receives only compact disease-defining context and performs packet-only classification without searching or deep research. Receipts and full provenance remain controller-owned and do not create independent research tasks.
- A curated concept chooses one member source-node ID as its run-local `concept_id`, retains member IDs and aliases, and uses one of `driver`, `mechanism`, `phenotype`, or `context`. A mechanism concept contains one pathological state or process at one causal level. Nodes merge only when the same pathological state, biological context, and profile fit every member; source-supported claims at different causal levels remain separate even when causally linked. Shared identifiers or biological relationships are not equivalence and are represented by source edges or researched assertions. Same-label gene-level disease claims may merge across sources, while mutation-, variant-, repeat-, model-, and mechanism-specific claims remain separate. This identity rule does not determine disposition. True duplicates remain as members of the retained concept, and Python rejects duplicate retained type-label pairs. Python requires an exact partition and does not perform fuzzy matching.
- `member_node_ids` is the compact curation evidence basis. Python projects each member and its
  source IDs into the frozen node, avoiding a second worker-authored evidence schema. A provisional
  model, genotype, compartment, or causal transfer may remain researchable when its assumption is
  explicit; it is not presented as direct evidence.
- Each curation concept contains `atomicity`. It is `null` for `context_only` and `exclude`. For `research`, it contains exactly `focal_abnormal_state`, `causal_level`, `biological_direction`, `compartment`, and `atomicity_rationale`, all as non-empty single strings. `focal_abnormal_state` names one source-supported changed biological variable or process. `causal_level` names the supported or explicitly transferred level. `biological_direction` states the proposed change rather than merely “abnormal” or “dysregulated.” `compartment` gives the supported or explicitly transferred context. `atomicity_rationale` explains why it is one intervention variable and distinguishes linked causes, consequences, assays, biomarkers, and outcomes. Provisional specificity states its model or transfer assumption rather than masquerading as direct evidence. Keep separately supplied claims distinct when they can occur independently, could justify distinct candidate-discovery routes, occupy different causal levels or compartments, or have materially different evidence. A supported nested or downstream mechanism is not demoted merely because it belongs to a broader process. A lone bundled source node may remain one broad exploratory research route when it names a usable abnormal process, but it cannot fabricate or separately seed unsupported subclaims. The concepts partition and `member_node_ids` are the sole split/merge record; `proposed_splits`, `merge_targets`, and parallel identity metadata are invalid.
- Concept type and disposition are separate judgments. Concept distinctness does not create a research job, and researchability may not be deferred to deep research. A concept is `research` only when the supplied packet already establishes a specific abnormal biological state or process, a specific well-supported causal lesion defining its own pathology route and biological direction, or a phenotype that passes every phenotype-research criterion below. A bare gene or gene-disease association, risk factor, model genotype, broad pathway, terminal outcome, or mutation label without supplied functional pathology is normally `context_only`. Generic gene and lesion-specific claims do not both create research routes unless each supplies a distinct intervention variable. Measurement-only biomarkers are `context_only`, while a biomarker-labelled causal process is classified by that mechanistic role, normally as a mechanism. A phenotype is `research` only when the supplied packet establishes all five conditions: it is disease-attributed rather than incidental, treatment-induced, age-related, or comorbid (disease-attributed does not mean disease-unique); it has a direct, source-supported causal or mechanistic link to a retained driver or mechanism rather than co-occurrence or graph proximity; it expresses one physiological state, direction, and supported compartment; it is an independent objective rather than a subordinate sign, measurement, severity descriptor, or manifestation substantially subsumed by changing an upstream retained concept; and it is material enough to preserve a major function or independently important disease burden and justify a separate candidate-discovery route. If any condition is absent or uncertain, the phenotype is `context_only` and links to relevant research concepts. Curation does not formulate a rescue state or assess drug availability; that direction is constructed only at the start of candidate seed research.
- Only `research` concepts receive deep work. Each `context_only` concept names at least one research concept in `related_concept_ids`; Python retains that administrative association in the frozen graph without creating an evidentiary edge or a separate research packet. `exclude` concepts remain visible in the curation artifact but do not enter the graph.
- Each researched concept returns one detailed, treatment-blind profile covering normal and pathological state, causal role, granular mechanisms, cell types, anatomy, timing, upstream causes, downstream consequences, contradictions, uncertainty, and gaps. It does not formulate a rescue state or candidate objective. Every materially distinct nested, causal, or downstream component is fully researched in `distinct_mechanisms`, with normal and pathological state, biological direction, causal level, compartment, focal relationship, limitations, and citations. Each entry is classified as `indexed_node` with an exact existing node ID, `focal_detail`, or `unindexed_distinct`. This preserves useful specific biology inside the frozen focal profile without duplicating another profile or dynamically adding graph nodes.
- Python assigns stable IDs to profile gaps and uncertainty, binds them to the profile node, and
  exposes them through graph context. Scope limits remain visible downstream but do not themselves
  delete the node or prevent exploratory seeding.
- `established_pathology_observations` is a list of `{observation, evidence_role, source_ids}` objects and may be empty. `evidence_role` distinguishes natural pathology from an experimental perturbation; workers retain causal biology but do not turn the perturbation into a candidate shortcut.
- `records.documents` must retain at least one researched source; supplied source metadata alone is not deep node research.
- Pathology discovery remains pathology-led and does not search for candidates, therapies, repurposing, or disease-drug associations. When an intervention appears in a source, profiles and assertions retain only directly supported causal biology and pathology; therapeutic interpretation, efficacy, candidate status, and trial history do not construct the pathology.
- Worker assertions are optional and contain only `subject_id`, `relation`, `object_id`, and a non-empty `evidence_context` list. Both endpoints must copy `node_id` values exactly from the packet's complete `allowed_assertion_nodes` index; aliases, cross-references, and newly researched entities are not endpoints. A mechanism without two allowed endpoints remains in the profile rather than creating a graph node. Each context records `source_ids`, `evidence_type` (`human`, `animal`, `cell`, `biochemical`, or `inferred`), `model`, `stage`, `polarity` (`supports` or `contradicts`), and one assertion-specific `summary`. Assertion-level source and summary fields are not duplicated. Assertions cite retained documents.
- Python merges assertions by `subject_id + relation + object_id`, unions sources only within otherwise identical evidence contexts, and assigns the stable assertion ID from that biological triple.
- Pathology nodes, edges, profiles, and assertions cannot contain treatment or candidate fields.

## Candidate records

After graph freezing, the open-question packet receives only the complete compact node index and bounded node lookup. It first generates a broad internal pool and returns one to ten materially distinct questions. Each question records the graph nodes that motivate it, why resolution matters, the exact `unresolved_basis`, and the `discriminating_evidence` that would resolve it. These are scientific descriptions rather than a gap taxonomy. The worker does not research answers, and graph proximity or shared terminology is not a missing biological relationship.

The question JSON is passed to the research packet with the same node access and a compact citation catalog; full source records are not copied into the handoff. For each question, the worker reconstructs the frozen baseline, performs a short discovery pass, and deepens research only when further information could materially change, constrain, or discriminate the answer. It chooses exactly one `research_disposition`: `corpus_sufficient`, `literature_delta_found`, or `still_unresolved`. There is no source or query quota, and redundant search results are not retained.

Each answer copies the question and graph nodes and records `frozen_baseline_claim_ids`, `counterevidence_claim_ids`, `alternative_explanation_claim_ids`, `material_answer_delta`, `saturation_reason`, limitations, and typed claims. Every claim contains `claim_id`, `claim`, `epistemic_status`, `delta_type`, `evidence_scope`, `assumptions`, and `source_ids`. `epistemic_status` is `direct_observation`, `synthesis`, or `inference`; `delta_type` is `baseline`, `extends`, `contradicts`, `discriminates`, `transfers`, or `defines_decisive_test`. Direct observations have no assumptions, while inference and transfer state them explicitly.

`corpus_sufficient` is answered entirely by exact frozen baseline claims, returns no new evidence for that answer, and records why the complete question is already resolved. `literature_delta_found` requires at least one non-baseline claim citing a newly retained document and states exactly how the answer changed; a fresh citation that restates a graph claim is not a delta. `still_unresolved` is partially answered or unresolved, retains no purported material delta, and records the missing discriminating evidence and saturation reason. A returned publication already present in the frozen corpus, including through a known publication alias or matching publication title, is not new evidence.

The synthesis packet receives those answers and the compact catalog and may add targeted verification or challenge sources. Its fresh worker generates a diverse internal pool, rejects graph restatements, reversed duplicates, label similarity, unsupported causal leaps, and unexamined remote transfer, and returns only materially distinct survivors. It returns exactly one `question_node_tags` row per supplied question, and every question tag and connection names all frozen nodes to which it is mechanistically relevant. Each connection includes at least one non-baseline claim from a `literature_delta_found` answer and names exact claims, mechanistic and rescue direction, why it is unexpected, assumptions, the strongest counterargument, weakest link, falsifying observation, non-empty limitations, and citations. These rows are not graph edges.

Each seed packet contains one frozen focal concept, a compact index of every retained non-anchor graph concept, the question answers and connections tagged with that focal node, and read-only commands for bounded node and connection context from the same snapshot. The seed task gives no direction to use, ignore, prefer, or discount the routed material. Focal and retrieved graph contexts keep source edges, researched assertions, and administrative `context_nodes` separate and omit pathology document metadata.

At the beginning of candidate seed research, before any drug search, the worker derives one or more `rescue_strategies` from the frozen focal pathology JSON, distinct mechanisms, graph context, and any materially useful routed questions or connections. It does not seek a numerical quota. Each strategy records a packet-local `strategy_key`, the focal `primary_node_id`, materially used `linked_node_ids`, `question_ids`, and `connection_ids`, a treatment-blind `search_basis`, the pathological and rescuable states, desired direction, mechanistic basis, ownership rationale, selected graph assertion and source-edge IDs, frozen pathology citations, and a route-specific search outcome and summary. `search_basis` contains only the biological target or process, desired direction, and pharmacological action searched. `search_outcome` is `seeded` or `no_supported_seed`. A seeded strategy must link to at least one candidate; an unproductive route remains visible as `no_supported_seed` and cannot be cited by a candidate.

`context_dispositions` accounts exactly once for every routed question and connection as `used`, `reviewed_not_used`, `not_relevant`, or `still_unresolved`. A used ID appears on at least one strategy; every other row gives a concise reason. This is an accountability ledger, not a requirement to use routed material.

The primary node is the node that contains the rescued state. Linked nodes provide source-backed causal or compensatory support and are not alternative homes for the same strategy. Administrative context nodes may prompt a relevant rescue-pathway check, but become linked nodes only when a source edge or researched assertion supplies the claimed relationship. Before submission the worker retrieves and compares every linked-node profile. It does not repeat the same state and route in reverse under a linked node; a materially different rescue objective, biological direction, or causal route is a separate strategy. Python rejects repeated strategies within a packet but does not perform semantic cross-node strategy canonicalisation. During aggregation it only assigns a stable namespace to each `(primary_node_id, strategy_key)` pair.

When a direct frozen-graph relation is available between a linked node and another strategy node,
the strategy selects the relation it actually uses or a retained synthesis connection spanning those
nodes. The absence of a direct graph relation does not block a profile-grounded exploratory route.

Candidate generation searches each retained strategy separately and keeps established drug action linked to one or more local `strategy_keys` as its main anchor. Each candidate carries:

- a preferred candidate name and every authoritative identifier found;
- one or more packet-local strategy keys;
- frozen graph node IDs;
- graph assertion IDs actually used and one concise graph rationale;
- source-edge IDs actually used;
- `pathology_source_ids`;
- `mechanism_source_ids` supporting the drug's action.

`graph_node_ids` includes the focal concept and may include any other indexed concept materially used by the hypothesis. The seed worker may retrieve such concepts through the supplied command but cannot alter the frozen graph.

`assertion_ids` lists only assertions materially used by the hypothesis. It may be empty when the focal profile is sufficient, in which case `graph_rationale` explains that choice. Every non-anchor endpoint of a selected assertion appears in `graph_node_ids`. `graph_rationale` explains the chosen graph support without repeating `mechanism_hypothesis`.

For every referenced strategy, the candidate's `graph_node_ids` include its primary and linked nodes and its `assertion_ids` include the strategy assertions. Candidate identity merging unions the mechanically namespaced strategy references, and review receives only the strategies actually linked to its candidates.

Strategy `source_ids` and candidate `pathology_source_ids` are subsets of the frozen pathology corpus. Candidate `mechanism_source_ids` are subsets of documents returned by seed research and include action evidence not already present in the frozen pathology corpus. Candidate-search documents cannot backfill a rescue strategy. Seed exclusions retain known identifiers, strategy links, a bounded reason code, a direct cited finding, and the concern. Their reason codes are limited to absent established action, wrong or opposite action, invalid entity, duplicate seed, or direct-derivation contamination; exact-disease prior art remains audit-owned.

For every `graph_node_id`, `pathology_source_ids` includes at least one source attached to that node, its profile, or an incident graph relation. The cited evidence must support the stated use of the context; graph proximity or topical similarity is insufficient.

Seed workers derive candidates from the supplied biological change and retrieve evidence connecting its target or process to established drug action. They do not use disease-specific drug literature or queries combining the disease with drug, treatment, therapy, trial, or repurposing terms. Such literature is reserved for candidate review and reported only when it changes the decision.

An experimental perturbation retained as causal pathology does not itself nominate that intervention. The same entity may be returned only after independent rescue derivation and with drug-action evidence not already present in the frozen pathology corpus.

A researched distinct mechanism or supplied linked graph node may support a specific causal, symptomatic, or compensatory route only when its relationship to the focal concept and candidate hypothesis is mechanistically justified.

Seed workers do not classify identity status. They retain every authoritative candidate identifier found. Python submits every supported identifier to UniChem, automatically merges only exact UCI matches, and queues every connectivity-only match, conflicting or partial mapping, unsupported identifier, and no result. A no-result record is unresolved, never evidence of uniqueness. The identity reviewer receives the entire queue plus a compact, controller-generated `canonical_candidate_options` list, so legal canonical IDs are explicit and possible aliases are not selected by name heuristics. Same-name matching never merges candidates automatically.

UniChem identifiers use their native database values under `chembl`, `drugbank`, `gtopdb`, `chebi`, `unii`, `pubchem_cid`, `drugcentral`, `inchi`, or `inchikey`. Other identifier types remain visible but are not rewritten or submitted speculatively.

The identity reviewer may attach a resolved queued group only to a candidate ID copied exactly from `canonical_candidate_options`, or partition queued seeds into new resolved, unresolved, or conflicting groups with a null `canonical_candidate_id`. Each option is either an existing resolved candidate or a queued exact-UCI block and names any queued seed IDs that the group must contain. UCI values appearing elsewhere in a partial or conflicting queue record are identity evidence, not canonical options. Seeds sharing one exact UCI are an indivisible identity block even when that block enters review because of a connectivity relationship. Each group cites newly retained authoritative identity evidence and partitions every submitted identifier exactly once among confirmed `identifiers`, `rejected_identifiers`, and `ambiguous_identifiers`. Python constructs canonical identity only from confirmed identifiers, retains the other buckets as provenance, validates complete non-overlapping queue coverage, and does not rewrite pathology or mechanism evidence. Each group may also retain cited `related_names` as `exact_candidate`, `same_active_moiety`, or `related_form`; these names expand downstream searching but never authorize a candidate merge.

Review packets retain the assigned candidates, the rescue strategies matching their `strategy_ids`, and all of their linked frozen pathology concepts and profiles, including complete cross-concept provenance, and include document metadata for the candidates' identity and drug-mechanism sources. Reviewers match IDs exactly and do not apply one candidate's strategy to another. For each candidate packets also contain `selected_graph_evidence`: researched assertions matching `assertion_ids` exactly and source edges matching `source_edge_ids` exactly. This removes source-overlap inference. Pathology citations remain attached to the frozen graph and candidate records without duplicating the full graph or pathology source library into every review packet. Workers first verify drug facts with primary or authoritative sources and map them to the supplied pathology, then check exact-disease prior art. It is an evidence dossier, not a decision: it contains a hypothesis, cited supporting findings, an explicit mechanistic bridge, assumptions, cited counterevidence, prior-art classification, supported aliases, and limitations. It does not score, rank, or exclude the candidate.

Each review candidate also carries deterministic `prior_art_terms`: its preferred identity name,
confirmed identifier values, cited related names, and retained member-seed names. The review reports every term plus each
newly supported alias in `prior_art.searched_terms`. Prior-art findings distinguish
`exact_candidate`, `same_active_moiety`, `related_form`, and `class_or_analogue`; only the first two
can support a positive prior-art status, and a finding cannot contradict a known identity relationship. Supporting, bridge, counterevidence, prior-art, and
limitation findings cite one exact retained locator per source and state evidence system,
direct-observation or inference status, and the entity form studied. A `none_found` status records a
bounded search outcome, not proof of absence.

Final candidate provenance exports strategy and selected assertion IDs directly; it never infers assertion use from endpoint incidence. A separate strategy export retains every seeded and `no_supported_seed` route, and `seed_exclusions.jsonl` preserves structured seed-stage exclusions. The seed aggregation notes report routed-context disposition counts. The summary reports the strategy count and compact graph coverage: candidate counts per non-anchor node, uncovered nodes, candidates using multiple nodes, and candidates using context-only nodes.

The audit packet contains the reviewed candidates, structured dossier evidence, seed-stage rescue strategies, complete frozen evidence graph, candidate-identity result, and a canonical index of the deduplicated retained corpus with inspectable passages or controller-retained source content. It withholds dossier hypotheses, mechanistic-bridge prose, prior-art status, and prior-art summary. A controller-generated index pairs each candidate first with every structured review, identity, mechanism, pathology, and explicitly linked graph citation, then supplements those links through meaningful confirmed identity terms and explicitly defined acronyms found in retained titles, locators, passages, abstracts, support text, or structured content. `evidence_dispositions` classifies every pair exactly once as exact-disease prior use or testing, relevant but not tested, name collision, or irrelevant; the novelty-failing class forces exclusion even when the paper arrived through another dossier. The auditor must use that closed corpus, independently weigh the argument and evidence, and partition every candidate exactly once. It must not search, add evidence, restate a dossier as analysis, request re-review, or defer a source judgment for later verification. Repurposing novelty is a binary gate: established exact-disease use, deliberate testing of the same active candidate in the exact disease or a disease-specific human, animal, cell, or organoid model with a disease-relevant endpoint, and registered exact-disease therapeutic studies are exclusionary regardless of outcome, controls, study quality, or interpretability. Proposals, reviews, patents, computational predictions, related-disease studies, class-level analogues, incidental exposure, and unresolved identity do not establish exact-disease testing. Long causal distance, weak evidence, uncertain exposure, and material assumptions remain scored reservations rather than exclusions.

Each assessment contains `source_integrity`, exactly four `component_scores`, a cited `net_assessment`, and cited `aliases` and `why_not` findings. `source_integrity` contains only `checks`; each check identifies one candidate-associated `source_id`, retained `locator`, entity relationship, exact scope (a bare component name, `net_assessment`, `aliases[n]`, `why_not[n]`, or routed review-counterevidence scope), a verdict of `supports`, `partly_supports`, `does_not_support`, or `contradicts`, and a concrete finding based on retained content. Python requires every cited source-use pair and review counterevidence use exactly once and rejects two identifier aliases for the same publication within one scope. Unsupported or contradictory evidence may be the complete retained evidence for a weak component; validation does not require a manufactured positive verdict. A flat status, generic declaration, or instruction to re-verify is invalid. Simple deterministic anomaly checks reject substantial reuse of hidden dossier conclusions, one long generic integrity finding repeated across three or more candidates, and an assessment that names none of its route's substantive biology. These are correction barriers, not scientific exclusions. The four components are `drug_action_confidence`, `disease_mechanism_relevance`, `mechanistic_bridge_plausibility`, and `translational_feasibility`. Each value may be any integer from 1 through 20. Counterevidence never earns positive scoring credit: it lowers each component whose premise it directly challenges and otherwise remains only an unscored `why_not` finding. The auditor writes `net_assessment` as complete, concise mechanistic prose connecting established drug action to the relevant disease mechanism and predicted correction or compensation, with the repurposing step identified as an inference. Card prose uses complete sentences rather than labels, clause fragments, keyword lists, or ellipses standing in for omitted content. Each score has a reason and retained `source_ids`; Python sums the values without weighting to a prioritisation score out of 80 and sorts descending by total, then candidate ID, with tied totals sharing a dense rank. The score is not a probability of efficacy. Final evidence cards contain only the preferred drug name, that cited mechanistic account, and the cited `why_not` findings; aliases, scores, component reasons, ranks, source-integrity checks, and audit metadata remain in their structured artifacts.

An exclusion contains `candidate_id`, a cited `finding`, `source_integrity` checks with scope `exclusion`, and one `reason_code`: `exact_disease_prior_use_or_testing`, `unsupported_action`, `opposite_action`, `impossible_translational_feasibility`, or `invalid_candidate`. The packet carries the exact definition of every code. In particular, missing downstream evidence is not an unsupported drug action, uncertainty is not demonstrated translational impossibility, and unresolved identity is not an invalid candidate. Review fields never enter final cards directly. Final outputs place the compact excluded-candidate list in `candidate_exclusions.csv`.

Only `status=complete` results are accepted. A failed preflight leaves the same packet ready and
the research result noncanonical; the worker corrects the exact invalid field and direct dependants,
then validates again. Conflicting replacement of an accepted result is rejected.
